# 1.升级说明 #
## 1.1.现状 ##

- 目前银行资管产品有一体化和微服务2个版本,产品升级维护都需要合并到2个版本中去，浪费很多人力和精力。
- 在产品维护过程中，经常需要启动多个微服务来调试代码，这里除了消耗大量的服务启动时间以外，还对运行微服务的计算机有较高的要求。

## 1.2.目的 ##   
- 本次升级改造的目的是解决上述问题。

## 1.3.升级思路 ## 
- 后端：将所有的微服务中服务的启动代码和配置全部移动一个新的工程中，该工程本身只提供服务集成和服务启动的能力，而该工程所提供的业务服务都是通过配置化集成起来的。
- 前端：将服务调用的地址配置在tams/application.yml配置文件中。
- 一体化：前端在pom.xml中集成上述的新工程即可。
